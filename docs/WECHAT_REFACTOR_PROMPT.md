## 3. 实施 W1–W3 中有依据的基础整理

### W1：职责与依赖

- 按微信文档 §10 收口 `third/wx` 与 `module/wx`。HTTP 入口和应用编排归模块，provider 协议、纯模板渲染及加解密归第三方适配。
- 修正 `WxBindService`、`WxMpOauthService`、`WxMpNoticeSendService` 等直接访问 UserProfileMapper 的边界；用户身份关联由 user 的公开 Service 及其不变量保护，不把 Mapper 换个目录继续跨模块使用。
- 固定形状使用具名 Request/BO/VO/provider DTO；保留协议本身需要的局部动态字段。业务快照不依赖微信 keyword，微信层不查询 Activity/PublicEvent Mapper 补快照。
- 保留 HTTP 和配置兼容；Java 包移动不要求客户端更换 URL。`WxClient` 是否拆分依据实际职责，不按方法数量拆出一堆转发类。
- 核实注释遗留、失效 TODO、重复 Builder 和旧适配入口，完成相关迁移后再删除。旧异步 payload reader 不能仅凭源码无调用就移除。

### W2：基础生命周期与失败保护

- 实施能力配置校验：未启用可选能力可以缺配置；显式启用的矛盾配置明确失败；模板 type 重复不能任选第一条。
- 核验凭据缓存的环境/账号/用途隔离、有效期、刷新并发与失效重试。复用项目基础设施和错误分类，不引入通用重试，不因超时重复远程写。
- 整理 scene/OAuth state 的主体、用途、期限与原子生命周期，覆盖并发、重放及换码/提交失败；不要删除 state 后丢失恢复语义。绑定冲突有歧义时不得覆盖或任取用户，产品策略缺失需单列。
- 按 §12 整理 URL/跳转边界、回调验签/解密/安全解析、账号路由、可信事件转换及状态 owner；provider ACK 不等于内部通用 success。
- 查官方协议确认具体 ACK/重投、token/code、URL 签名等规则。无法核验的协议变化独立标记 BLOCKED；继续结构、安全解析和其他可证明保护，不伪造协议或宣称可靠。
- 保留 audit 的关联/版本/幂等保证及 notify 的执行所有权/结果收尾，远程调用不进入本地业务事务。重要回调不能吞异常 ACK 后仅留日志，也不为所有事件机械创建新的通用 Inbox。
- 清除本次受影响链路的敏感日志；遵循现有 Observability 的 ID、分类和指标约定。

### W3：通知与模板适配

- 必须同时执行微信文档 §16 的配置专项及 §17 的既有渠道恢复决定：区分业务通知定义、渠道绑定、provider 模板/环境绑定和运行时资格。核对当前实际代码，不能只整理 YAML 或复制历史差距表。
- 检查 NotifyType → 消息产品/模板的完整绑定、source/formatter/default/required、跳转占位符和 JSON 冻结快照类型。明确枚举支持、模板已配置与真实可发送三个边界，避免过严的自造校验误挡合法配置。
- 让 H5 入口、规划、发送共用静态就绪判定；授权入口无需用户已有授权，但整体授权消费/发送能力未实现时不能展示为可用。保留 enabled 与 subscribe-visible 的不同语义，逐用户许可不能由 YAML 模拟。
- 遵循微信文档 §17 的恢复决定：既有 legacy 服务号通知由微信权威校验订阅资格，不再用固定 false 全局阻断，也不伪装为永久 permission=true。新 canonical 渠道仍需独立证据；旧 v1 Job 无 Delivery 尝试历史，保留读取及受控处置，不自动重放。

- 独立区分小程序订阅消息、服务号订阅通知、服务号模板消息，禁止失败后自动切换产品/账号/渠道。
- 按通知文档及微信 §1–5、§8 整理模板、字段来源、页面跳转、资格检查与投递结果，不重定义 Notification/Delivery/Job 状态机。
- Preference、capability、provider permission 分开。H5 success、绑定或关注均不能直接写成永久授权。
- 同时检查 canonical 和 legacy 发送入口；已知缺模板/关闭/缺身份的路径不得继续发送；既有服务号的 provider 校验模式不能用于绕过新 canonical 门禁。
- 新渠道没有真实模板、许可模型或账号证据时保持 unavailable。可以完成明确的内部结构和本地映射验证，不编造授权次数、真实 templateId、SDK 能力或已发送结果，不为了“接通”新增空 Adapter 骨架。
- 维护必要兼容，不自动产生历史 Delivery、重置 UNKNOWN 或补发。模板/账号变更需处理待发送项的兼容，不能静默解释旧 payload。
