# 业务边界与当前决定

本文只保留仍需开发者遵守的业务决定，按主题维护当前结论，不追加“后文覆盖前文”的阶段记录。不包含接口字段清单、数据库 DDL、测试次数或部署完成声明。
这些决定是对既有需求的整理；修改决定应先明确业务含义，再检查协议和实现依赖。对外协议由 [contracts](../../contracts/README.md) 定义；本文不替代完整契约。

## 活动与公共事项

- 活动与公共事项由运维维护并直接发布，当前不接审核。公共事项继续由 exam 模块承载，不因名称不同新建统一 event 主表。
- 发布状态、事项阶段、报名状态是不同维度；历史审核状态不能代替公开可见性判断。
- 下架允许修改后重新发布；取消不能恢复。已发布内容保存立即生效。提前结束、取消、下架是不同用例。
- 活动和公共事项共享正文、参与入口、媒体和时间线能力；主体资格由所属业务模块判断。
- 订阅与正式报名独立。activity_enrollment、exam_subscription 表示订阅，不能用其人数消耗正式报名名额；报名也不自动建立订阅。
- 主页公共事项倒计时以时间线节点为候选，订阅仍以事项为单位；每个事项只展示距离当前最近的一个未来节点，该节点到期后重新读取时再推进到后续节点。没有显式未来节点时，未来的事项开始时间作为“事项开始”兜底节点。
- 人数容量和团队容量区分单位，未知容量不能解释为零名额。开始、结束、报名窗口分别表达含义；待定或仅日期信息不能伪装成精确时刻。

## 活动个人表单

- 平台个人表单属于活动能力，公共事项当前不支持平台表单。外部报名和无需报名仍是独立参与方式。
- 同一用户与活动保留一条逻辑报名记录；取消后重新提交复用记录。报名有效数与名额约束必须在并发操作下成立。
- 首次提交后冻结表单定义，不能通过取消或作废全部报名解除冻结。
- 答案仅本人及获授权管理员可见，公开表单定义不能包含他人答案。
- 开放受 activity.registration.enabled 控制，默认关闭。关闭时不接受新的平台报名，但保留必要的历史查询、取消和管理能力；实际环境是否开启必须核实。
- 开放前需要真实接口、客户端与数据迁移验收，存在代码和局部测试不等于已经上线。

## 媒体与用户资料

- 存储对象归属由服务端校验，不能仅凭客户端 URL 认定拥有媒体。稳定附件 ID 和 objectKey 分别承担关联身份与存储身份。
- 用户资料保存用例返回本次提交的最终服务端资料，调用方可以据此更新共享状态。后续审核仍可能改变资料，这不是永久审核通过的承诺。

## 新增与未定义需求

本文未列出全部产品规则，也不把代码当前行为自动提升为业务决定。
修改现有功能时先检查对应 contracts 覆盖情况及相关实现/测试；缺失的业务含义在本次需求中明确，不从旧阶段记录、Mock 或页面外观推导新规则。
验收结果记录在对应任务或发布证据中，不混入长期规则。新增稳定业务决定时更新对应主题，不复制一套开发指南。
