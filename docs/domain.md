# 业务边界与当前决定

本文只保留仍需开发者遵守的业务决定，按主题维护当前结论，不追加“后文覆盖前文”的阶段记录。不包含接口字段清单、数据库 DDL、测试次数或部署完成声明。
这些决定是对既有需求的整理；修改决定应先明确业务含义，再检查协议和实现依赖。对外协议由 [contracts](../../contracts/README.md) 定义；本文不替代完整契约。

## 积分申请与账务

业务及 HTTP 权威为 [Points V1 Contract](../../contracts/docs/coordination/points-v1/README.md) 的 `points-v1-r6` 及[统一基线](../../contracts/docs/coordination/person-identity-org-auth-unified-v1.md)。新申请除四阶段、已核实 ACTIVE 身份和账号安全外，还要求明确获准受理的当前有效组织与同一成员周期；无组织不允许新申报，但保留普通校园功能和个人全部历史。申请按唯一原受理组织授权，不以审核一单取得该人跨组织完整账务或材料。退出再加入不复活旧申请审核资格；本人受控结束旧单后另行申报。双统计分别按当前成员全部个人历史净额和原受理组织净额计算，冲正沿原流水归属。准入组织及维护权限未获确定时不能自行开启资格。

人员局部成员维护只证明该组织关系，不证明完整个人集合或完整组织花名册；A 范围不能修改 B，统一政治身份仍须完整组织范围覆盖或 PERSON 直授。具体当前实现边界见[人员基础](person-foundation.md)。Points 已实现受理周期、本人结束、独立职责和双统计；受理资格及花名册完整性仍须明确可信证据，旧隔离 r2 结果不能视为新策略验收，见[积分实现边界](points.md)。

正常核分1～10，审核说明可省略；批准与唯一原始 GRANT 同一事务提交，历史核定不改写；驳回不记账。Ledger 仅追加，完整撤销及原子改分为独立 POINTS_CORRECTION 授权动作，须同时具有读取、发起调整与批准调整能力，拒绝自审及冲正本人积分。改分仅以同一 correctionId 的 REVERSAL＋CORRECTION_GRANT 替换当前未冲正正向节点，撤销/改分须提供 reason/basis；合法历史纠错不依赖申请人当前成员、绑定、阶段或ACTIVE状态，管理员当前授权仍须有效。不修改原批准/授予历史，不新增自动计分、余额缓存、排名、兑换、周期清零或其他业务自动积分。通知依既有 owner 在业务事务中可靠受理后独立投递；`points.result-notification` Job 与终审/冲正同事务受理，Worker 复核意图保存的 Person 与同一当前可信绑定/可接收账号，换绑/解绑留依据跳过，依赖故障不冒充跳过；改分只受理一条 POINT_GRANT_CORRECTED；结果仅以 SYSTEM/IN_APP 文本通知投递，不含备注/材料/签名/跳转。结果通知默认接入，无独立启用开关；消费者兼容仍需联调验证。

Person 是独立业务主体，真实姓名归档案；User 是账号与操作者，不要求普通账号建档。积分申请、账本和余额归 Person，原提交 User/Binding、受理依据和实际操作账号不可改写；历史误绑不自动迁移。已提交材料经业务授权读取，旧账号草稿、所有文件与通知不迁移。Learning 分 PERSON/ACCOUNT 责任，按 assignmentId 完成，之后绑定不吞并既有责任。正式答疑保存原作者和当时 Person/Binding/Qualification 证明。具体持久化与授权边界见[人员基础](person-foundation.md)。
积分材料支持图片、PDF、Word、MP4视频（现有单文件10MiB上限）；图片须取得微信明确内容安全通过结果才可登记，待定/未知不放行。PDF、Word和视频保留上传但暂不做内容审核，仍校验格式、大小、所有权及私有ACL。各模块已有视频功能当前不做自动内容审核，仍保留原有权限和格式/大小/所有权检查。图片、文字及视频封面/海报的既有检查不因此取消。

## 活动与公共事项

- 活动与公共事项由运维维护并直接发布，当前不接审核。公共事项继续由 exam 模块承载，不因名称不同新建统一 event 主表。
- Activity 与 PublicEvent 是两个独立业务模型，各自拥有发布/生命周期判断与 Reminder Policy；只共享 Timeline、正文、媒体、Reminder/Notification/Async 基础设施，不建立统一 Event 状态机或按 subjectType 分支的通用业务规则引擎。
- 发布状态、事项阶段、报名状态是不同维度；历史审核状态不能代替公开可见性判断。
- 下架允许修改后重新发布；取消不能恢复。已发布内容保存立即生效。提前结束、取消、下架是不同用例。
- 活动和公共事项共享正文、参与入口、媒体和时间线能力；主体资格由所属业务模块判断。
- 评论、点赞、分享、浏览及其公开列表/计数须读取主体当前公开资格，不能用记录存在或存在性缓存代替。Activity/PublicEvent 以未删除且 PUBLISHED 为公开依据，历史审核状态、受众发现筛选与正式参与资格不替代发布状态；已发布但结束/取消的主体仍保留公开互动。Post 沿其自身发布与审核可见规则，NORMAL / MENTOR_QA 的临时公开仅由同步前置检查通过的受理版本取得，截止固定且读取时生效。评论互动还须验证真实所属主体及有效根线程；主体撤下不删除历史评论/互动事实，重新公开后按当前资格读取。
- Timeline 是 Activity/PublicEvent 的唯一业务时间事实。提醒时刻由各自 Policy 从精确 Timeline 节点与已确认偏移推导；不得恢复主体表历史时间列，也不得把主页公共事项倒计时当成 push Reminder。
- 只有 `PUBLISHED + ACTIVE` 且未自然结束的 Activity 可以产生 Reminder；草稿、下架、取消、结束不产生。Activity 在 sendAt 已到但业务锚点未到时可补当前必要提醒；PublicEvent 保持未来计划规则。重新发布基于当前 Timeline 重新计算。Activity Reminder V1 的完整规则和实现边界统一归 [提醒设计 §2、§11](reminder-notification.md#2-reminder-policy)；PublicEvent 保持独立 Policy，不随 Activity V1 扩张。offset 不进入稳定 rule identity。
- 订阅与正式报名独立。activity_enrollment、exam_subscription 表示订阅，不能用其人数消耗正式报名名额；报名也不自动建立订阅。
- Reminder Plan 是否存在不取决于当时有无接收者；到期 fan-out 再解析当前接收者。具体集合由所属 Policy 与业务 owner 决定并按 userId 去重，不以自动订阅代替报名者的参与提醒资格。PublicEvent 第一版仍面向订阅者。
- 主页公共事项倒计时以精确的未来 Timeline 节点为候选，订阅仍以事项为单位；每个事项只展示距离当前最近的一个未来节点，该节点到期后重新读取时再推进到后续节点。没有符合条件的 Timeline 节点时不展示倒计时，不回退到主体表历史时间列。
- 人数容量和团队容量区分单位，未知容量不能解释为零名额。开始、结束、报名窗口分别表达含义；待定或仅日期信息不能伪装成精确时刻。
- Activity 草稿参与形式可未确定，使用 NULL 表示、API 省略 participantMode；历史 0 仍表示未知，不能默认为个人。个人/团队明确设置后保留，发布或已发布编辑必须为合法明确值；参与形式与容量单位及平台个人表单约束分别校验，不从缺失字段推断个人容量或报名。

## 账号资格

- 有效封禁禁止普通认证业务操作与新登录，历史用户内容、互动、订阅和报名事实保留；公开匿名入口不因此变成认证接口。普通请求在验证 Sa 登录事实后读取当前数据库账号资格，不以 Session.role、旧账号缓存或一次 kickout 成功作兜底。状态来源失败、缺失或非法不得解释为正常。
- 禁言只按既有规则限制内容创建，普通读取、点赞及订阅不因此全面封禁；管理端仍保留其独立 loginType、NORMAL 管理资格和 QR activation/撤销信任链，不扩大旧管理员权限。
- 限制采用服务端有效截止时间；已到期的限制按现有数据库条件更新恢复。封禁在User owner事务中推进session_version，旧普通/admin凭证及旧QR候选在显式解封或到期恢复后均不复活，需重新登录；kickout只是存储清理优化，失败不削弱持久失效边界。封禁提交不依赖清除正向授权缓存，不新增此类缓存；提交前已开始的请求不承诺强制中断。

## 提醒与业务通知

- Reminder 表示从业务时间派生的未来意图；取消、时间变更、报名成功等事件型通知不经过 Reminder Plan。哪些事件必须通知需要各业务明确，基础设施不能从状态变化自行推导。
- Activity V1 的重要时间确定/变化/撤回、整体地点变化、取消和显式提前结束按 [提醒设计 §2.2](reminder-notification.md#22-activity-reminder-v1-业务关系与主动变化) 判断，接收者为订阅者与有效平台报名者并集；不包含报名成功/取消，也不建立兜底 `ACTIVITY_UPDATED`。该设计不宣称现有代码已完成。
- PublicEvent 第一版主动通知包含取消、影响用户行动的语义时间变化，以及具有真实 location 语义节点的位置变化，接收者为订阅者。当前普通 `END` 状态不能证明“提前结束”，在增加明确的 lifecycle event/reason 前不产生 `PUBLIC_EVENT_ENDED_EARLY`。
- Notification 是每用户的稳定通知内容事实；`IN_APP` 是本地渠道，只有其 Delivery 生效时才进入用户收件箱。外部渠道是否配置、用户是否绑定微信、投递是否成功都不回滚 Notification，也不改变其他渠道结果。
- Notification 创建时冻结标题、正文和必要的渠道无关业务快照，点击目标仍读取主体最新状态。微信 templateId、openid、provider 状态等不是业务通知内容。
- Delivery 是 Notification 的逐渠道派生状态。`IN_APP` 可在本地事务内完成，不创建远程 Job；两个微信渠道各自持久化结果。站内成功不代表微信送达，任一微信失败也不能回滚 Notification 或 `IN_APP`。
- 通知类别第一版为 `ACTIVITY`、`PUBLIC_EVENT`，按 Category × Channel 使用 sparse override；Activity/PublicEvent 普通提醒均为 `USER_CONFIGURABLE`。当前没有确认的 `MANDATORY` NotificationType；未来账号安全类必须通知不得复用或受这两个类别的关闭开关影响。
- 详细的计划、幂等、取消、fan-out、Delivery 与微信边界见 [Reminder、Notification 与 Delivery 设计](reminder-notification.md) 和 [WeChat Integration](wechat-integration.md)。
- 已持久化的开始/截止提醒允许在提醒时刻之后、对应精确业务节点之前恢复；达到该节点后停止新的提醒 fan-out/外部调用，不撤销已有站内事实。普通介绍或附件编辑不创造新提醒意图，不因保存版本增长重复提醒。
- 群体通知第一版按执行时有效订阅/报名关系分批解析，不保存事件时全量接收者快照；执行前新加入者可能收到，已退出者按当前资格排除，当前短批次存在有界竞态。完成后不为新加入者重跑；具体恢复规则见通知文档。固定接收者的评论/回复/资料审核事件保持固定 receiver。
- 主动事件在业务提交时冻结事件身份和变化内容，连续真实变化保留为不同事实，不承诺异步到达顺序。取消/提前结束事件不受 Reminder 的 ACTIVE 限制；消息表达事件时内容，详情反映最新状态。
- IN_APP 关闭只影响未来初始规划，已有消息与阅读状态保持；微信调用前重新检查当前偏好。重复事件不按后来配置补建原来未规划的渠道，重开不触发历史补发。评论/回复/审核等既有设置保持原 owner，不自动并入活动/公共事项六组合。

- Activity stage 从唯一 ACTIVITY_START 按原精度计算：精确范围到 endTime 结束，日期范围包含最后一天；单点只判断开始，不编造结束。缺失、TEXT 或歧义为 UNKNOWN；运营终态优先，自然结束不改存储 lifecycle，也不能通过编辑时间重开。
- 普通平台报名及修改在主开始关闭，持续性必须显式 allowRegistrationAfterStart=true，仍受报名 END 和可靠主结束约束。未知主开始仍按既有报名窗口；日期不转换成精确午夜。
- 取消报名先验证当前 ETag；已取消重试幂等。未删除、ACTIVE、未结束的 SUBMITTED 可取消；普通活动在主开始前允许取消，即使报名截止已过，主开始未知时以可靠报名 END 为上界，无上界拒绝。持续性取消只受报名 END 和主结束约束。撤下本身不禁止取消。
- 报名工作区候选按活动名称字面子串分页，名单、候选和统计各自核验当前报名读取职责。当前授权范围是 ACTIVITY PLATFORM，保留合法独立来源与就绪 owner 能力。活动目录权限、受众、主办方和创建者不提供报名读取资格。
- 本人历史列表保留所有报名关系，只展示最近公开的必要摘要；撤下后的私有编辑不能泄露，缺可信摘要时明确不可用。内部状态3公开统一为 CANCELLED，保留内部证据，取消时间只用可信既存时间，不伪造。
- Activity 软删除只允许 DRAFT/UNPUBLISHED，任何报名历史均阻止删除；删除和报名争用同一主体锁。恢复为 UNPUBLISHED，保留生命周期、表单版本、正文和订阅，不恢复提醒。统计独立使用报名 READ 职责，以单次数据库快照读取有效、取消、总报名和订阅人数。

## 活动个人表单

- 平台个人表单属于活动能力，公共事项当前不支持平台表单。外部报名和无需报名仍是独立参与方式。
- 外部报名及平台表单加外部步骤在发布、在线编辑时至少有一个合法参与入口；不限定入口类型为外部报名。入口可用说明、URL 或附件表达，具体类型的校验仍按共享契约执行；纯外部报名不配置平台表单。
- 同一用户与活动保留一条逻辑报名记录；取消后重新提交复用记录。报名有效数与名额约束必须在并发操作下成立。
- 首次发布后冻结表单 fields 的结构、标签、选项和用途，allowModification 仍可调整；暂时移除再启用也保留原 fields/formVersion。有历史报名后不可移除平台能力或改成团队名额，平台与混合模式可合法互换。
- 答案仅本人及获授权管理员可见，公开表单定义不能包含他人答案。
- 平台报名默认接入，无独立启用开关；是否可报名取决于活动发布/生命周期、精确报名时间窗、容量及当前用户资格。
- 开放前需要真实接口、客户端与数据迁移验收，存在代码和局部测试不等于已经上线。

## 媒体与用户资料

- 存储对象归属由服务端校验，不能仅凭客户端 URL 认定拥有媒体。稳定附件 ID 和 objectKey 分别承担关联身份与存储身份。
- 独立管理附件登记后为有期限的 CANDIDATE，技术核验与内容审核分开；业务首次保存（包括草稿）与全部实际引用原子接管后成为 FORMAL。失败、取消、登记重试都不延长候选期限；解除引用不删除正式附件。V74 前可信历史记录保持正式。登记必需 Idempotency-Key；同身份/同键/同字段值回放同一资源当前状态，同托管对象跨键也只登记一个资源。外部 URL 保留合法登记，但不绑定本站原始上传记录。
- 软删除内容保留文件，不以不可见、审核拒绝、下架或取消自动推导永久清除；当前没有软删除到期清除规则。明确永久清除或媒体替换时，媒体 owner 在内容事务内写入删除意图，再由清理任务回收；可复用附件仍有效或被其他主体引用时保留。本人正式附件列表沿管理附件读取规则先按当前可读用途及本人资格筛选，再分页/计数，排除候选、他人及已删资源；独立删除仅允许当前有效管理身份的上传者本人，当前引用及历史审核保留阻止删除；删除与新增引用争用同一附件锁。帖子／评论永久清除用例仍未提供。
- 新增附件引用要求本人上传资格、当前业务管理权限及用途/类型匹配；有权业务管理者可保留、排序或解除该业务既有他人引用，不获得跨业务新增引用或独立删除权。普通媒体/头像继续各自引用协议，保存前核验服务端快照；不强制创建 Attachment。
- 用户资料的全部指定字段必须完成必要安全检查后原子生效；明确拒绝或检查未完成时保留有效资料，不依赖补偿或后台自动生效。新旧写入口共享此保证，迟到审核不得改写资料。保存返回最终服务端资料；公开昵称允许重复，运营标志来自内部身份事实。协议以 [User/Profile contract](../../contracts/docs/coordination/user-profile-homepage.md) 为准。

## 学习任务

LearningTask 的业务权威是冻结的 [LearningTask Contract](../../contracts/docs/coordination/learning-task.md) 及其 canonical Schema/operations；不复用 Article 发布状态、活动报名、确认审核或通用审批流。Backend 当前领域实现、数据库保护和未接通依赖见 [LearningTask](learning-task.md)。领域实现与 HTTP 可用、外部依赖集成、生产启用分别验收，不根据有表或定向测试推断上线。

帖子及评论图片的公开读取以当前主体/节点/线程及实际引用为准，文件ID与历史URL存在不授予权限。待审作者预览仍为本人私有；管理隐藏不扩大匿名读取，作者删除不开放作者预览。已移除的图片不能借旧文件URL继续读取；公开状态变化对后续 GET/HEAD/Range 请求生效，不承诺撤回已下载副本。历史 COS 公有副本在云端切换完成前仍有直链边界，不能以新 Backend 入口代替历史迁移证据。

## Post 内容组织与导师答疑

NORMAL / MENTOR_QA 的共用跨端生命周期以[普通社区 Contract](../../contracts/docs/coordination/post-community.md)为准；无 Person、组织或导师资格门槛。创建先完成账号、合成内容、附件归属及同步文字检查，受理与可选原键收据同事务；媒体未齐才可有 acceptedAt 起最多十分钟的临时公开，到期读取即退出。NORMAL 允许纯图片，QA 必须有非空正文及适用分类；作者私有资源与公开主页分开。作者删除终态与管理隐藏独立，安全受限作者可修正，管理隐藏不能用编辑复活；恢复要求可证明管理来源、未作者删除且当前安全通过。

NORMAL / MENTOR_QA 的 thread 读取保留有公开合法回复的删除/隐藏根占位，不输出其正文、图片或原作者；新受理的共用 thread 回复可存续，历史隐藏回复不自动重曝。公开评论数按实际节点事实计算，占位不计。两类 Post 及其评论点赞均不新增通知；收藏和最近浏览只读本人关系，失效目标不输出内容。浏览按账号/帖/北京时间业务日同事务去重并更新最近历史，历史到 lastViewedAt+90天即时不可读，清空不清统计去重。带 eventId 的可观测分享按账号唯一且异义冲突。举报结案固定覆盖 reportIds、实际动作和脱敏结果，与通知事实同事务成立；成立保留不要求下架。

类型、字典和答疑的跨端行为以 [Post Contract](../../contracts/docs/coordination/post-organization-mentor-qa.md) 为准。PostType 首批 NORMAL / MENTOR_QA，创建后不变；历史默认 NORMAL，旧列表及 liked 缺省仅 NORMAL。分类与话题由独立管理权限维护；禁用保留历史引用，显式新选/重交拒绝，省略保留。Category 适用范围不能移除仍被任何历史 Post 引用的类型。话题顺序保存在关联表，最多三个，不用关联 join 扩大分页行数。

PATCH 仅作者可用：GET view=edit 返回无包装的可编辑表示及完整强 ETag；提交前检查候选，提交事务内重新校验表示、权限及引用并更新 revision。独立 audit_revision 隔离初次创建审核与已检查的编辑；POST_EDIT 只保存候选审核事实，回调不发布内容。详情、字典投影和权限读取不使用跨身份详情缓存。

QA 无 parentId 的一级为正式回答，要求 questionVersion 和可发言 User 当前经管理员确认的 ADMIN_MANUAL 绑定、ACTIVE Person / 导师资格；管理权限不授予作答资格。二级为普通讨论，正常用户均可参加，无 Person/导师或回复方向限制，必须指向同问题、同根、可见的具体评论，接收者由服务端推导。当前 PersistentMentorQualification 读取 Person 主库事实，可信来源未知返回 503，可靠无资格返回 403；资格事实与有效期在受理及首次公开提交前独立复核。名单自助认证与导师核准规则见[人员基础](person-foundation.md#党建名单)。

正式回答受理固定原 User、Person、绑定与核准来源、历史姓名/职务/单位及核验时间；首次公开固定公开时间。currentCertification 只查询原 User+Person 当前组合，失效或重绑不改历史归属、不抹去已合法公开回答；来源不可确认单独返回 UNAVAILABLE。问题内容版本独立于强 ETag 和审核版本，实际标题/正文/图片变更才推进；分类/话题及同值提交不推进。首次公开与问题编辑、资格撤销/解绑按事务锁裁决；改题先发生，旧候选保留私有并标记 QUESTION_CHANGED；回答先公开，问题内容永久保护，即使所有答案后来失效也不能解锁。

qaSummary 只统计当前公开合法正式根，普通讨论、占位、未公开、删除/隐藏不计；历史证明未知不能伪造零回答。answerState 仅显式 MENTOR_QA 支持，先筛选再分页并绑定 cursor。本人帖子/回答及收藏/历史列表缺省 NORMAL，显式 MENTOR_QA / ALL 扩展类型，仍按原账号所有权读取。恢复正式回答须有可证明的首次合法公开、管理隐藏、安全通过及原问题版本，作者删除和未首次公开候选不能借恢复绕过；历史合法回答恢复不要求今天仍具导师资格。

Comment、审核后计数及 POST_COMMENTED / COMMENT_REPLIED 通知继续共用；正式回答首次真正公开只向提问者通知一次，排除自己，重放/恢复不重复。QA 二级必须有具体目标；无具体目标的 NORMAL 历史回复保持原根作者通知语义。升级和停止旧 writer 的边界见 [数据库入口](../src/main/resources/db/README.md#导师问答证据-v82)。

## 官方宣传内容 M01

独立富文本资讯使用 [Article Contract](../../contracts/docs/coordination/article.md)，Backend 状态、媒体及启用边界见 [Article](article.md)。Article 不继承或迁移本节 M01 数据，两个集合和旧入口分别保留。

官方内容使用统一分类组织资讯、支部动态、通知宣传、e 网同心、信息红、E·安全、先进事迹和成果。仅独立管理员会话的 content:manage 可创建或维护；发布单位为展示字段，不能授予普通用户可信来源。正文纯文本，图片和一个视频复用已登记附件；无额外审核和自动通知。创建为 DRAFT，人工确认后 PUBLISHED，撤下为 UNPUBLISHED；首次 publishedAt 保留，已发布内容不回到 DRAFT。普通 Post、评论、点赞及数据不被迁移或改写。编辑以强 ETag 防止覆盖，主体和附件引用在同一事务保存。

## 成长档案与主动政治生日分享

成长记录是 Post 与稳定 Person、发布时精确党支部、GROWTH / POLITICAL_BIRTHDAY 的固定关联，分类和话题不能建立、迁移或解除该关联。发布资格取可信当前绑定、ACTIVE Person、正式有效身份及精确有效党支部成员事实；政治生日分享限预备党员和正式党员，不维护纪念日期、不自动生成记录或提醒。

本人历史以当前 Person 读取，换绑后的新账号不继承旧 User 的修改、删除权。原 User 必须仍可信绑定同一 Person 才能删除；编辑还必须保持原组织及类型的当前发布资格。组织成员只读当前组织可见安全版本；作者删除退出本人及组织读取，管理隐藏仅保留本人私有历史和获准管理访问。普通列表、搜索、本人普通内容、喜欢、收藏和浏览集合排除成长关联。

私有图片沿成长上传上下文登记和正式接管；原作者、评论作者、旧通知、文件 ID 或旧链接均不能替代当前根内容授权。VIDEO 在完整技术和内容检查不可用时返回 503，不借可信作者或人工审核补齐。具体字段、跨操作约束和验收依据为 [成长协调](../../contracts/docs/coordination/growth-record.md) 及其 canonical operations。
